# iOS and shared mobile source

See `ITEM10_IOS_IPADOS_PRODUCT.md` for the current queue/lifecycle/recovery,
browser data/download management and build-admission changes. Development builds
now require `tools/build_ios.py --development`; `--destination simulator` selects
the simulator product build. Archives require release resources, a signing team
and an explicit reviewed `--export-compliance` classification. These changes do
not establish Apple SDK/device/store readiness or close the remaining source.

The resource assembly shares the explicit desktop/Android core inventory. It removes stale generated assets before copying the current set, so retired cores cannot remain bundled through the Xcode folder reference. Manifest-declared artifacts require matching WASM size/hash and accompanying license notices; release assembly still requires explicit distribution approval.

The iOS product now has authored Swift/UIKit/WebKit source, a native Rust static-library boundary and a generated Xcode project. It has not been built, launched in a simulator, signed or exercised on a device. The current resource assembly is explicitly a development assembly with no emulator binary. This is implementation progress, not a claim of App Store readiness.

`platform/local-service` shares the actual transfer and background-import modules with the desktop broker, and dispatches the same Rust library, save, compatibility, performance, assistance and lifecycle operations. It does not duplicate SQLite/save-conflict rules in JavaScript. `platform/mobile` exposes a bounded C ABI for a trusted Swift/JNI host. A profile handle binds every renderer request to one native-selected data directory and profile UUID. Returned buffers have an explicit owned-allocation/free contract and are cleared when released. The renderer command entry point is separate from the trusted native picker authorization entry point.

The iOS Game Hub uses its own nonpersistent WKWebView data store. Its resources are immutable app-bundled HTML, JS and approved source-built WASM. A loopback-only ephemeral HTTP server provides a secure-context-compatible origin for WebKit workers and audio worklets. A random path capability and a strict public-resource inventory constrain the server; it has no HTTP filesystem, save, library or native-control API. Native messages require the exact owning WKWebView, main frame, scheme/host/port and capability path. Browsing WebViews have no Game Hub message handler. The app does not request an alternative-engine or JIT entitlement, and does not download native emulator code after installation.

Native single-file import uses the system picker, scoped resource access and an NSFileCoordinator read while copying a bounded regular file into private staging. Rust receives a native-granted file descriptor through a UUID capability; Javascript receives neither path nor arbitrary file access. The private staging pathname is unlinked after Rust opens its descriptor, so the final library import does not retain a second named ROM copy. Save, diagnostic and performance export first creates a private output capability, commits through the same Rust logic, and then presents the system export picker. A cancelled export does not falsely report successful destination delivery. A separate native folder picker now connects scoped, coordinated lazy readers to the common CUE/M3U importer and advertises the authored disc capability. All provider/device and mobile runtime qualification remains outstanding; see `IOS_DISC_IMPORT.md`.

The native browser surface has HTTP/HTTPS address entry, back/forward/reload, up to 32 tabs, separate private-tab website storage, local bookmarks/history, restoration of nonprivate tabs and origin-scoped WebKit media permission prompts. No website receives the Rust bridge. Private tabs are omitted from automatic history/session persistence, while a user can explicitly bookmark a page. Downloads require an explicit native decision, have a two-GiB/twenty-minute bound, are never executed or imported automatically and are exported through the system share UI. Browser history and game data are separate. Further browser/profile controls, cookie/site-data management, complete bookmark management, authentication/download edge cases and localization remain required.

The Game Hub uses shared touch/controller/keyboard code, responsive mobile layout and an iOS fullscreen presentation fallback. It checks actual WASM/graphics capabilities instead of inventing GPU or performance results. A lifecycle suspension request pauses the worker and attempts in-game plus snapshot saves through the bridge before ending a bounded native background task. Operating-system task expiry, termination or stalled storage can prevent a final save; previously committed atomic saves are retained. Device verification must cover this explicitly. WebKit process termination restores native navigation and is shown as a recoverable stopped session, not silently presented as continued gameplay. Library pages use compact summaries and backend filters; full disc manifests are requested only when opening one game.

The initial mobile local policy deliberately disables desktop executable launch, the desktop updater, telemetry upload and encrypted cloud synchronization until mobile-specific integrations exist. The source plan still requires mobile synchronization, remote streaming and applicable approved native/no-JIT adapters; these remain unfinished requirements. The local library, exports and play path do not depend on an account. Default profile data and local browser state are marked excluded from automatic cloud backup, with OS file protection enabled; explicit user exports remain under the user's control.

`tools/assemble_ios.py --without-cores` generates the development bundle inventory and deterministic Xcode project without compiling or testing. A release assembly refuses an empty/unapproved/revoked core catalog. `tools/build_ios.py` describes the later explicit Mac build: Rust iOS/Apple-Silicon-simulator static libraries, XCFramework creation, unsigned device build or an archive using a real explicitly supplied signing team. The initial recipe does not cover Intel-host simulator slices. No Apple SDK or signing identity exists in the current Windows authoring environment. A production app icon, complete notices/source offers, release metadata, export-compliance determination, current App Store/privacy review and real device evidence remain required.

The checked-in privacy declaration currently lists no app-developer collection or tracking and documents app-local preferences/timestamps/timers. It is an authored declaration requiring a final binary/dependency API audit, not an independently established compliance result. The browser's user-selected website traffic remains website traffic and is not claimed to be anonymous.

Primary references used while authoring: [WebKit reply message handler](https://developer.apple.com/documentation/webkit/wkscriptmessagehandlerwithreply), [UIKit document picker](https://developer.apple.com/documentation/uikit/uidocumentpickerviewcontroller), [ATS local-network policy](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking), [required-reason API declarations](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype), [WebKit media permission delegate](https://developer.apple.com/documentation/webkit/wkuidelegate/webview(_:requestmediacapturepermissionfor:initiatedbyframe:type:decisionhandler:)), [upstream WKDownload interface](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/Cocoa/WKDownload.h).

Explicit device snapshots now augment the bounded Rust base report on the main queue through public ProcessInfo/UIDevice APIs. The prior battery-monitoring flag is restored after collection; unavailable initial values stay unknown. Reported OS thermal state is separate from measured throttling. GPU/driver/available-memory adapters, privacy/store review and final device qualification remain required. No iOS API or build has run. See `DEVICE_INFORMATION.md`.

Native profile opening now supplies a retained, serialized Keychain device-credential provider through a separate bounded C callback ABI. Fixed service/profile items use non-synchronizing WhenUnlockedThisDeviceOnly storage; the root/recovery seed is not persisted. Account commands and one explicit foreground sync worker are now authored with coalesced lifecycle cancellation independent of serialized request I/O; legacy opens keep sync unavailable. No account, network, credential, Keychain/Swift API, compiler, simulator, device or test has run. See `MOBILE_CREDENTIALS.md` and `MOBILE_SYNC.md` for cooperative cancellation limits and remaining background/device/store work.

The shared disc importer now has a scoped native-reader source and bounded/profile-bound callback ABI; optional lengths and actual copied bytes feed the existing parser/hash/manifest path. The iOS adapter now uses a security-scoped selected root, bounded metadata enumeration, descriptor-relative no-follow traversal, lazy tokens, a coordinated producer with a bounded consumer slot, cooperative cancellation and final-owner scope/budget retirement. Document generation, pending reply deadlines, picker cancellation and native detach are connected in source. The privacy manifest includes user-selected file metadata. No provider/file/import API, SDK/compiler or test has run. See `IOS_DISC_IMPORT.md` and `NATIVE_DISC_PROVIDERS.md`.

## Non-JIT Core Runtime, Remote Play Bridge, File Provider & L10n (Batch 04)

Source implementation added covering items 67–72:
- `NoJitCoreAdapter.swift` (Item 67): Non-JIT interpreter compliance (App Store Guideline 2.5.2), memory cap enforcement (max 512 MiB per instance), and memory pressure/jetsam avoidance.
